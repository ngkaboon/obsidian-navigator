**Goal:** A new `prune` skill that cleans up stale `raw/index.md` entries
and dangling wiki `Sources` citations after raw files are deleted, with
safety guards against a scan bug wiping the whole index — plus an opt-in
`prune` step wired into the existing `brain-sync` pipeline.

**Architecture:** One new skill file (`prune/SKILL.md`) sibling to
`trim-llm`/`reindex`/`wiki-update`, plus an edit to the existing
`brain-sync/SKILL.md` to add a new opt-in argument. No code, no pytest —
these are process-documentation deliverables. "Testing" means: (a) running
the read-only stale-detection command against the real vault right now to
confirm it behaves correctly on today's data (expected: finds nothing,
since nothing's been deleted yet), and (b) verifying file structure/
frontmatter/wiring by inspection. The destructive path (removing a real
stale entry) can only be exercised once a raw file has actually been
deleted, which isn't something to manufacture against the user's real
vault just to test — so full destructive-path testing happens the first
time the user genuinely deletes a raw file and runs `prune` for real, in a
vault-rooted session (same constraint documented for `brain-sync`: the
Skill tool can't be invoked for a `disable-model-invocation` skill from a
session rooted elsewhere).

**Tech Stack:** Markdown + YAML frontmatter (skill format), bash (grep/ls
diff logic), Read/Edit (precise block removal, matching `trim-llm`'s
style).

## Global Constraints

- Skill frontmatter: `disable-model-invocation: true` (matches
  `trim-llm`, `reindex`, `wiki-update`, `brain-sync`).
- Anomaly circuit-breaker: abort with zero edits if `ls raw/*.md` returns
  nothing while `raw/index.md` has entries, OR if the stale list exceeds
  half of all indexed entries.
- Preview-and-confirm gate: list every title to be removed and every wiki
  page to be edited, and wait for explicit user confirmation, before any
  edit is made.
- `raw/index.md` block removal: precise Read-then-Edit removal of the
  exact `### [[Title]]` block plus one adjacent `---` separator — not a
  scripted regex substitution.
- Wiki edits limited to removing the specific stale `- [[Title]] (raw/)`
  Sources bullet — no other page content touched.
- `wiki/log.md` gets one new append-only entry per pruned title:
  `## [YYYY-MM-DD] prune | Title — removed from index; removed from
  Sources on: Page A, Page B` (or `no wiki citations found`).
- `brain-sync` integration: new opt-in argument `prune`, pipeline order
  `trim` (if passed) → `prune` (if passed) → `reindex` → `wiki-update` →
  `refresh.sh`.

```markdown
# Prune

Cleans up after deleted raw files: removes their stale `raw/index.md`
entries and any dangling `Sources` citations in `wiki/` pages.

## Current index state

- Indexed files: !`grep -o '\[\[.*\]\]' "raw/index.md" | sed 's/\[\[//;s/\]\]//' | sort`
- All raw files: !`ls raw/ | grep '\.md$' | grep -v '^index\.md$' | sed 's/\.md$//' | sort`

## Task

1. **Find stale entries.** Compare the two lists above. Titles present in
   the indexed-files list with no matching entry in the all-raw-files list
   are stale (the reverse of what `reindex` checks — `reindex` looks for
   files not yet indexed; this looks for index entries with no file).

2. **Anomaly circuit-breaker.** Before doing anything else:
   - If the all-raw-files list is completely empty while the indexed-files
     list has one or more entries, STOP immediately. Make no edits.
     Report: "raw/ scan returned no files but the index has N entries —
     this looks like a directory or scan error, not a real mass deletion.
     Verify you're in the vault root and raw/ is populated, then re-run."
   - If the stale list has more entries than half of the indexed-files
     list, STOP immediately. Make no edits. Report the stale count vs.
     total indexed count and ask the user to confirm this large a
     deletion was intentional before re-running.
   - Otherwise, continue to step 3.

3. If the stale list is empty: report "No stale entries found" and stop.

4. **Preview and confirm.** Before editing anything:
   - For each stale title, grep `wiki/*.md` for a Sources bullet citing it
     (format: `- [[Title]] (raw/)`) to find which wiki pages, if any, cite
     it.
   - Present the full plan to the user: every title about to be removed
     from `raw/index.md`, and for each, every wiki page about to have a
     Sources bullet removed.
   - Wait for explicit confirmation before proceeding. If the user
     declines, stop with no edits made and report that nothing was
     changed.

5. Once confirmed, for each stale title:
   a. **Remove its `raw/index.md` block.** Read the file, locate the
      exact `### [[Title]]` block (from the heading down to just before
      the next `### ` heading or end of file), and remove it along with
      one adjacent `---` separator line, so spacing around the remaining
      blocks stays consistent with the file's existing convention. Use
      Edit for a precise, read-first-then-edit removal — not a scripted
      regex substitution, since block content varies and titles may
      contain characters that are awkward to pattern-match safely in
      bash.
   b. **Strip dangling wiki citations.** Remove the Sources bullet
      identified during the preview step from each affected wiki page —
      no other edits to that page (its synthesized prose stays; only the
      citation for the now-deleted file goes).
   c. **Log it.** Append one line to `wiki/log.md`:
      `## [YYYY-MM-DD] prune | Title — removed from index; removed from
      Sources on: Page A, Page B` (or `no wiki citations found` if 5b
      matched nothing).

## Report

- If stopped by the circuit-breaker: report which guard tripped and why,
  and that no edits were made.
- If no stale entries: report "No stale entries found."
- If the user declined at the confirmation step: report that nothing was
  changed.
- Otherwise: for each stale title pruned, confirm it was removed from the
  index and list which wiki pages (if any) had a Sources bullet removed.
```
